  <action>
    Rewrite frontend/src/pages/WorkspacePage.tsx to orchestrate the full data pipeline UI. The page is a state machine driven by `pipelineStage` from the Zustand store.

    **Layout structure (inside AppShell):**
    ```
    [QuickDetailedToggle]
    [PromptInput + SourceChips row]
    [UploadDropzone | ColumnMappingTable]
    [AssumptionsBanner (quick) | AssumptionsChecklist (detailed)]
    [JobStatusCard (during fetch)]
    [FrequencyMismatchDialog (modal overlay)]
    [DataPreviewPanel (after data ready)]
    ```

    **State machine flow:**

    Stage "idle" (initial):
    - Show empty state: heading "Ready when you are", body copy per Copywriting Contract
    - Show PromptInput (enabled) + QuickDetailedToggle + UploadDropzone

    Stage "parsing" (after prompt submit):
    - PromptInput disabled
    - Call `apiFetch<PromptParseResponse>("/data/parse-prompt", { method: "POST", body: JSON.stringify({ prompt, mode }) })`
    - On success: setSources(response.sources), setPipelineStage("confirming_sources")
    - On error: inline error message, reset to idle

    Stage "confirming_sources":
    - Show source chips (one per source)
    - Source chip onOverride: call `apiFetch("/data/parse-prompt/override", ...)`, updateSource with result
    - Source chip onRemove: removeSource(index)
    - "Fetch Data" button below chips (or reuse PromptInput submit)
    - If mode === "detailed": show AssumptionsChecklist before fetch
    - On fetch click: create job via `apiFetch("/data/fetch", { method: "POST", body: JSON.stringify({ sources, date_range, mode }) })`, setJobId, setPipelineStage("fetching")

    Stage "fetching":
    - Show JobStatusCard with jobId
    - Poll via existing TanStack Query (JobStatusCard handles this internally)
    - Also poll /data/preview/{jobId} to check for data_ready or frequency_conflict:
      - If frequency_conflict: setFrequencyConflict(conflict), setPipelineStage("frequency_conflict")
      - If data_ready: setPreview(data), setPipelineStage("preview_ready")

    Stage "frequency_conflict":
    - Show FrequencyMismatchDialog (overlay, blocking)
    - onConfirm: setResolution(choice), call /data/resolve-frequency, setPipelineStage("fetching")
    - onCancel: reset()

    Stage "confirming_assumptions" (detailed mode only):
    - Show AssumptionsChecklist
    - On confirm: proceed to fetch

    Stage "preview_ready":
    - Show DataPreviewPanel with preview data
    - Show AssumptionsBanner (if quick mode) or assumptions inline
    - "Run Analysis" button in DataPreviewPanel -- this will be wired in Phase 3

    **Upload flow (parallel path):**
    - UploadDropzone onUpload: setUploadResult(result), show ColumnMappingTable
    - ColumnMappingTable onConfirm: POST /data/upload/confirm-mapping, store mapping
    - Upload data can then be combined with API data in the fetch flow

    **Error handling:**
    - API errors: catch in each handler, inline error message (not toast for now)
    - Network errors: "Could not reach {source}. Check your connection and try again." per Copywriting Contract

    **Key implementation notes:**
    - Remove the DEV-only test job button from Phase 1
    - Keep AppShell wrapper
    - Use `useAnalysisStore()` for all state -- no local component state for pipeline flow
    - Spacing: use UI-SPEC spacing scale (md=16px between elements, lg=24px between sections, xl=32px between major sections)
  </action>
