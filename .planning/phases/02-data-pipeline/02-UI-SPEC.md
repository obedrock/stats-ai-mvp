## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, chip gap between icon and label |
| sm | 8px | Compact element spacing, chip internal padding, badge padding |
| md | 16px | Default element spacing, card padding, panel section gaps |
| lg | 24px | Section padding, workspace vertical rhythm |
| xl | 32px | Layout gaps between major workspace sections |
| 2xl | 48px | Major section breaks (e.g., between upload area and preview panel) |
| 3xl | 64px | Page-level spacing (not expected to be used in this phase) |

Exceptions:
- Touch targets (sidebar buttons, chip actions, dialog buttons): minimum 44px height — established in Phase 1 Sidebar. Apply to all interactive chips and dialog action buttons in this phase.
- Frequency mismatch dialog and assumptions checklist items: 40px row height minimum for legibility at data-dense widths.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 (regular) | 1.5 |
| Label | 12px | 400 (regular) | 1.4 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 28px | 600 (semibold) | 1.2 |

Notes:
- Body (14px/400/1.5) is the established baseline from `index.css` `@layer base`.
- Label (12px) is used for step labels in JobStatusCard (established pattern: `text-[12px]`), column stats, and chip metadata.
- Heading (20px) is the current WorkspacePage h1 size (`text-xl font-semibold`).
- Display (28px/semibold) matches the sidebar wordmark "Stats-AI" (`text-[28px] font-semibold`). Use only for the page-level heading if a full-page state warrants it; not needed for most Phase 2 components.

## Color

All values sourced from `frontend/src/index.css` `:root` tokens. Dark theme is the permanent default.

| Role | Token | Hex | Usage |
|------|-------|-----|-------|
| Dominant (60%) | `--background` | `#0f172a` (slate-950) | Page background, workspace background |
| Secondary (30%) | `--card` / `--secondary` / `--sidebar` | `#1e293b` (slate-800) | Cards, sidebar, data preview panel background, upload area background, dialog background |
| Border/Divider | `--border` / `--input` | `#334155` (slate-700) | All borders, separators, input outlines, table cell borders, chip outlines |
| Muted text | `--muted-foreground` | `#94a3b8` (slate-400) | Secondary labels, column stats, placeholder text, pending stage labels, elapsed time |
| Foreground | `--foreground` / `--card-foreground` | `#f1f5f9` (slate-100) | Primary text, active labels, chip text |
| Accent (10%) | `--primary` / `--accent` | `#6366f1` (indigo-500) | Active step connectors in progress track, primary CTA button fill, source chip border on hover/active state, Quick/Detailed toggle active side, ring focus |
| Destructive | `--destructive` | `#ef4444` (red-500) | Cancel Job button, destructive dialog confirmation button, invalid series error badge, malformed file parse errors |

Accent reserved for:
1. Primary CTA button fill ("Fetch Data", "Run Analysis")
2. Active step connectors and dots in the job progress track
3. Source chip border/highlight when a chip is in edit mode
4. Quick/Detailed toggle active-side indicator
5. Focus ring on all interactive elements (already `--ring: #6366f1`)

Second semantic color: `#ef4444` (red-500 / destructive) — reserved for destructive actions (cancel confirmation), validation errors on series IDs, and malformed upload error messages. Do not use for warnings; warnings use `--muted-foreground` slate-400 with italic text.

## Interaction Contracts

### Source Chips (D-01, D-03)

- After prompt is parsed, 1–N chips render below the prompt input.
- Chip anatomy: icon (FRED or Yahoo logo placeholder using Lucide `Database` / `TrendingUp`) + source label + series ID + `X` remove button.
- Chip default state: border `--border` (#334155), text `--foreground` (#f1f5f9), background `--card` (#1e293b).
- Chip edit state (click to open): border changes to `--accent` (#6366f1), Popover opens with an Input pre-filled with the current series ID and a "Confirm" button.
- Chip error state (invalid series ID): border `--destructive` (#ef4444), red Badge overlay "Invalid — click to fix".
- Chips animate in with a 150ms fade; removal animates out 100ms fade.

### Upload Dropzone (D-08)

- Default state: dashed border `--border`, background `--card`, centered text "Drop CSV, Excel, or JSON here — or click to browse" in `--muted-foreground`.
- Drag-over state: border switches to `--accent` (#6366f1), background lightens to `#1e3a5f` (a blue-tinted slate, using inline style or a one-off class — not a token).
- File accepted: replaced by ColumnMappingTable immediately. No intermediate "uploading" spinner unless file parse takes >500ms, in which case show a single Lucide `Loader2` spinning at 20px centered in the dropzone area.
- File rejected (wrong type): shake animation (tw-animate-css `animate-shake`), error text in `--destructive` appears below the dropzone for 4 seconds then fades.

### Column Mapping Table (D-09, D-13, D-14)

- Shows first 5–10 rows as a preview.
- Each column has: column name (bold, 14px), detected type dropdown (numeric / date / text / category), role selector (dependent var / independent var / date index / ignore).
- Rows with type coercion issues shown with a yellow dot indicator (use `#f59e0b` — chart-3 token) in the column header — not red, because the issue is correctable.
- "Confirm Mapping" button (primary, accent fill) is disabled until all columns have a role assigned or "ignore".
- Auto-fix report appears above the table as a collapsed `<details>`-style Collapsible: "3 rows dropped, 2 values coerced — click to see details."

### Frequency Mismatch Dialog (D-05, D-06, D-07)

- Full-screen overlay Dialog (shadcn Dialog, not drawer).
- Heading: "Data frequencies do not match" (20px, semibold).
- Body: Describes actual data counts (e.g., "AAPL: 3,200 daily rows · GDP: 92 quarterly rows") using 14px body text.
- System recommendation displayed as a highlighted option card (background slightly lighter than card, border `--accent`): "Recommended: aggregate AAPL to quarterly via mean."
- Alternative options listed below as radio options (shadcn RadioGroup): aggregate to lower frequency (mean / last / sum), interpolate to higher frequency, abort.
- Dialog footer: "Confirm" (primary button, accent fill) and "Cancel analysis" (ghost button). No X close button — dialog is blocking by design (D-07).
- Dialog cannot be dismissed by clicking outside (set `onInteractOutside` to `preventDefault`).

### Data Preview Panel (D-11)

- Implemented as a shadcn Card below the prompt area, collapsed by default (Collapsible with trigger "Show data preview (N rows)").
- Expanded state: scrollable table (max-height 320px, overflow-y scroll) showing first 50 rows.
- Table header row: column names in 12px label weight 400, background `--muted` (#1e293b).
- Below the table: a stats bar showing per-column min / max / mean / missing count in 12px text, muted color. Stats are separated by `·` delimiters. Scrollable horizontally.
- "Run Analysis" button (primary, accent fill) appears at the bottom right of the panel only when preview is open.

### Assumptions Banner (D-12 Quick mode)

- Collapsible banner pinned to top of the workspace content area (not fixed to viewport).
- Collapsed label: "Assumptions applied — click to review" in 12px muted text with a Lucide `ChevronDown` icon.
- Expanded: bulleted list of assumption strings (14px body, `--foreground`). Each assumption is a single sentence, past tense (e.g., "Used log-transformed GDP", "CPI expressed as % change").
- Banner background: `#1e293b` (--card), border-bottom `--border`.

### Assumptions Checklist (D-13 Detailed mode)

- Rendered as a form before execution, replacing the Run button until submitted.
- Each item: shadcn Checkbox (checked = recommended default pre-applied) + label string (14px).
- "Confirm and fetch data" button (primary, accent fill) appears below the list — disabled until at least one item is checked.
- Toggle between Quick and Detailed mode does not reset previously confirmed assumptions.

### Quick/Detailed Toggle (D-14)

- Rendered as a small two-option toggle (shadcn Tabs with `size="sm"` or Toggle) directly below the prompt input, left-aligned.
- Active side: `--accent` (#6366f1) indicator. Inactive side: `--muted-foreground` text.
- Label: "Quick" / "Detailed". No icons needed.
- State persists to localStorage key `stats-ai:analysis-mode` (Zustand store with persistence).

### Job Progress Card — Fetching Data Stage (existing JobStatusCard extension)

- The "Fetching data" stage step (already in STAGES array in JobStatusCard.tsx) gains a sub-status line: "Fetching FRED: GDPC1…" in 12px muted text below the progress track.
- Sub-status updates as each parallel source fetch completes (polling at 2s returns stage metadata from Celery task).
- No other changes to the existing JobStatusCard visual design.

## States Required Per Component

Every interactive component in this phase must implement all applicable states:

| Component | States Required |
|-----------|----------------|
| PromptInput | default, focus, disabled (during fetch), character-limit warning |
| SourceChip | default, hover, edit-open, error (invalid series), removing |
| UploadDropzone | default, drag-over, uploading, error |
| ColumnMappingTable | default, column-error (coercion warning), confirm-ready |
| FrequencyMismatchDialog | open (only state — dialog is always blocking when shown) |
| DataPreviewPanel | collapsed, expanded, loading (skeleton rows) |
| AssumptionsBanner | collapsed, expanded |
| AssumptionsChecklist | unchecked default, checked, confirm-disabled, confirm-enabled |
| QuickDetailedToggle | quick-active, detailed-active |
| FetchProgressCard | queued, fetching (with sub-status), done, error, cancelled |

Loading states use the existing `animate-pulse` pattern from JobStatusCard. Skeleton rows in DataPreviewPanel use slate-800 placeholder divs at the same height as table rows.
